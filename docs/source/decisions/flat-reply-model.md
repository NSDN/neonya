# 2026-10-30 扁平流 + 引用即回复

## 背景

讨论主题详情页的回复形态：是照传统 BBS 的「楼层 + 楼中楼」，还是照现代社区的时间流。
同时要解决一个实际问题——**阅读者看不出某条回复后面还有多少讨论**，导致难以在中途插话。

## 讨论脉络

### 回复形态

- **楼中楼两层（旧方案）**
  - 优点：局部讨论聚在一起，父子关系明确。
  - 缺点：父子都在流里出现，同一条内容要读两遍；子回复被埋在主楼之下，时间上「死掉」。
- **无限嵌套（树形）**
  - 优点：逻辑上完整。
  - 缺点：回复一多，层数失控，窄屏无法渲染；查询与分页成本持续上升。
- **扁平流（Discourse 式）**
  - 优点：所有内容按时间线性排列，新讨论永远可见；分页简单（游标）。
  - 缺点：子讨论容易散落，长链难追。
- **扁平流 + 树形链视图（Discourse 之外的增强）**
  - 优点：长链可聚焦。
  - 缺点：树视图仍要渲染层数；且「只看这条链」会把「后面还有多少讨论」的问题换一种形式再出现。

### 「看不出后面有多少讨论」的解法

- 引用快照（只显示被引文本）→ 无法得知后续讨论量。
- 内联展开父帖 → 同上。
- **被引用索引（backlinks）**→ 在被引条目底部直接列出「哪些条目引用了它」，数量与序号一目了然，同时天然成为插话入口。

## 决策

采用 **扁平流 + 引用即回复 + 被引用索引**：

1. 所有条目按 `post_number` 线性排列，**不做嵌套**，最大缩进恒为 1；
2. 回复某条 = 写入 `reply_to_post_id`（单边），并附**被引文本快照** `quoted_excerpt`（≤ 500 字），原帖被编辑或删除后引用仍可读；
3. 引用块显示元信息（`引 #8 · @作者 · 时间`），支持「展开片段全文」（块内）与「跳转到被引用条目」（锚点 `#post-{N}`）；
4. 每个条目底部显示**被引用索引**：`WHERE reply_to_post_id = $1`，默认前 3 条，超过 8 条折叠；
5. 回复主题本身不显示引用块；划句引用主题正文时目标为 `#1`（首条）；
6. 不做树形链视图。

## 影响

- **数据**：`posts` 增加 `post_number` / `reply_to_post_id` / `quoted_excerpt` / `quoted_is_full` / `quoted_offsets`；删除 `parent_id` / `root_post_id` / `floor`。
- **新表**：`topic_reads`（`last_read_post_number` + `notification_level`），无限流的未读定位与通知等级依赖它。
- **分页**：`?after={postNumber}` 游标，取消 `?page=N`。
- **通知**：`reply_to_post_id` 驱动回复通知，同一 `(user, topic)` 15 分钟内去重；划句引用不额外通知。
- **索引**：`posts(topic_id, post_number)` 覆盖流与游标，`posts(reply_to_post_id)` 覆盖被引用索引。
- **前端**：见 [条目布局与交互](/design/post-entry-layout)。
- **扩展**：多引用（一条引多条）留到 M2，用 `post_quotes` 侧表，可由 `reply_to_post_id` 回填。
