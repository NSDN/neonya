# 2026-10-29 依赖更新的分阶段策略

## 背景

仓库同时包含 Vue 3 前端、VitePress 文档站与 Go 后端，三者的依赖生态独立演进，且长期未做系统性巡检。  
盘点时发现多个包已跨过多个大版本（vite 6→8、vue-tsc 2→3、typescript 5→7、gin 1.11→1.12、pnpm 10→12），
一次性全部升级会让「构建失败到底是哪个包导致的」无法定位。

需要确定一套可重复执行的升级策略，并写进文档，让后续维护者（含 AI session）照做。

## 讨论脉络

### 记录位置

- **`decisions/`**：现有 ADR 模板是「背景 → 讨论脉络 → 决策 → 影响」，写一次性取舍；升级流程是反复执行的 checklist，混入会把 ADR 撑成操作手册。
- **`develop-description/`**：语义是「怎么改这套文档站」，且内容已过时。
- **`reference/`**：只放外部参考资料。
- **新建 `maintenance/`**：语义独立，可容纳后续其他操作类文档（发版、迁移、备份）。

决定新建 `maintenance/` 放流程正文，本文件只保留策略层的取舍。

### 升级粒度

- **方案 A：全部依赖一次升到 latest** — 省事；但失败面叠加，`pnpm-lock` 与 `go.sum` 同时变动，回滚只能整体回退。
- **方案 B：按风险分阶段，一阶段一提交** — 提交变多；但每阶段可独立验证、独立回滚，失败定位成本最低。

决定方案 B。

### 阶段划分依据

- 补丁 / 次要版本零代码改动，先清掉大部分陈旧版本（阶段 1、2 补丁档）。
- 构建链（vite + plugin-vue + vue-tsc + typescript）互相约束，必须成套升级（阶段 3）。
- 框架大版本（pinia 4、vue-router 5）改动面在业务代码，且 vue-router 5 反向要求 vite ≥7.3，只能排在构建链之后（阶段 4）。
- 工具链与容器镜像影响构建可复现性，与依赖升级解耦（阶段 5）。
- 清理类改动（弃用依赖、无引用依赖）与语义修正单独收尾（阶段 6）。

### `typescript` 的版本上限

TypeScript 7 是编译器原生重写版本，`vue-tsc` 3 的 peer 只声明 `>=5.0.0`，无法确认其与 7.x 的兼容性。  
选择停在 6.x：6.0.3 是 JS 实现线的最后版本，`@vue/tsconfig` 0.9.1 的 peer 要求 `>=5.8` 也能满足。

### 容器镜像是否钉版本

- **保持 `latest`**：无需维护；但构建结果不可复现，PostgreSQL 大版本升级会在某次重启后静默发生。
- **钉具体版本**：需定期手动维护；但数据目录布局、基础镜像的行为都变可控。

决定钉版本，并在当前数据库尚无真实数据时尽早执行——`postgres:latest` 一旦承载数据，大版本变更就意味着迁移或数据丢失。

## 决策

依赖与工具更新采用**分阶段、一阶段一提交**的方式，具体操作步骤与验收清单见[依赖与工具更新流程](/maintenance/dependency-update)。

- 阶段顺序：基线 → 前端补丁 → 后端补丁 → 构建链大版本 → 框架大版本 → 工具链与镜像 → 清理。
- 每个阶段必须通过统一的验收清单后才能进入下一阶段。
- `typescript` 上限为 6.x，`vitepress` 上限为 1.x。
- 容器镜像与数据库镜像钉具体版本，构建工具版本由 `go.mod` 与 `Containerfile` 共同约束。
- 策略变更时更新本文件，流程细节变更时更新 `maintenance/dependency-update.md`。

## 影响

- 新增 `docs/source/maintenance/`，并在 VitePress 侧边栏与导航中增加「维护手册」入口。
- `AGENTS.md` 增加 Maintenance 指针，引导后续 session 在升级前查阅该目录。
- 每次升级后需回填 `dependency-update.md` 的版本矩阵与「已完成更新记录」。
- 升级提交统一使用 `chore(deps):` / `chore(tooling):` 前缀，便于按阶段回滚。

## 2026-10-30 修订：策略有效，阶段清单重写

「按风险分阶段、一阶段一提交」的策略保留（含钿版本与提交前缀两项）。原阶段清单基于 Vue 3 + Vite + Gin，已不适用。

新版阶段划分：

1. **补丁 / 次要版本**：`pnpm -r update`，无代码改动；
2. **构建链成套升级**：Next + React + TypeScript——三者 peer 互相约束，必须同一提交；
3. **文档站构建链**：VitePress + Vite + Vue，与 `web` 独立，可单独升；
4. **Go 侧**：`go get -u ./...` 后跑 `task check`；`pgx` / `chi` / `huma` 优先，`sqlc` / `goose` 解耦；
5. **工具链与镜像**：`podman machine`、基础镜像、`sqlc` / `goose` 版本；
6. **清理**：彻底不用的依赖与 lockfile 冗余。

两处失效：

- 「`typescript` 上限 6.x」——原依据是 `vue-tsc` 的 peer 约束，新版随 Next 支持的版本走；
- 「`vitepress` 上限 1.x」——升主版时单独提交即可，不需要长期钉住。

流程细节见 [依赖与工具更新流程](/maintenance/dependency-update)。
