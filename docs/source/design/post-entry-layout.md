# 条目布局与交互

> 状态：草案（M1 前定稿）
> 关联决策：[扁平流 + 引用即回复](/decisions/flat-reply-model)
> 数据字段：见 `architecture/data-model.md` § 引用模型

本文定义主题详情页的**条目（post）**长什么样、有哪些可交互元素，以及元素与数据字段的对应关系。
元素用稳定编号标记（`A1`、`S3`…），讨论时直接引用编号，例如「`S3` 这个版本先不做」。

---

## 0. 术语（只约束中文文案，代码仍用 `topic` / `post`）

| 概念 | 中文 | 英文 / 字段 | 禁用 |
| --- | --- | --- | --- |
| 整个讨论 | **主题** | `topics` / topic | 帖子、楼 |
| 主题内的单条内容 | **条目**（量词：条） | `posts` / post | 楼、楼层、评论 |
| 序号 | **`#N`**（读作「第 N 条」） | `posts.post_number` | 楼层号 |
| 第一条（主题正文） | **首条** / 主题正文 | `post_number = 1` | 主楼、1 楼 |
| 发表主题的人 | **作者** | `author` | 楼主 |
| 只看发表主题者 | **只看作者** | OP only（`S3`） | 只看楼主 |
| 对某条做回应 | **回复**（= 引用） | `reply_to_post_id` | 引用回复、楼中楼 |
| 被引用下来的文字 | **引用** | `quoted_excerpt` | |
| 引用了本条的条目列表 | **被引用** | backlinks（`B1`） | 反向链接 |

文案示例：

```
引用块      引 #8 · @Other · 2h ago
被引用      被 3 条引用： #30 @C · #42 @D · #57 @E
通知        @A 在《主题名》中回复了你 · #12
分享链接     /t/{topicId}#post-12
编辑器按钮   回复（选中文字后浮出「引用」）
空状态       还没有人回复这条，来说两句？
```

---

## 1. 核心模型

**所有条目都在同一条扁平流里，不做嵌套。回复即引用。**

| 场景 | 引用块 | 通知 |
| --- | --- | --- |
| 回复主题 | 不显示 | 主题作者 |
| 引用主题正文（全文 / 划句） | 显示，目标是 `#1` | 主题作者 |
| 引用某条（全文 / 划句） | 显示，目标是该条 | 该条作者 |
| 回复某条但删掉引用块 | 不显示 | 该条作者 |

嵌套层数**恒为 1**。链式关系通过「引用块 + 被引用索引 + 锚点跳转」表达，不做树形视图。

## 4. 交互规则

1. **用户卡片用点击触发**（点 `U1`+`U2` 区域），不使用 hover，避免误触。
2. **`A3` 回复**：点击后预填引用块（全文引用）。用户可删掉引用块 → 变成「回复了但没有引用」，仍保留通知。
3. **划句引用**：在 `C1` 内选中文字 → 浮出「引用」→ 预填选中片段（`quoted_is_full = false`）。
4. **`B1` 被引用索引**同时是「中间插话」的入口：点最新一条即可继续该子讨论。
5. **锚点**统一为 `#post-{post_number}`，分享链接指向 `#post-12` 而非 `#12`，避免与标题锚点冲突。
6. **无限流**：`S5` 跳到未读位置；首次访问且无未读记录时落在最新一条。
